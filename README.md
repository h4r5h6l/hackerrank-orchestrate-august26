# HackerRank Orchestrate

Starter repository for the **HackerRank Orchestrate** 24-hour hackathon.

## Task: Message Notification Router

Build an AI-powered system for WhatsApp that decides which messages deserve immediate attention, which should wait, and which should be muted.

The system must reason over multimodal messages, including text messages, image posters/screenshots, and voice notes.

WhatsApp is noisy. A user can receive family chats, society notices, school updates, co-worker messages, business account promotions, image posters, voice notes, and scams in the same message stream. Treating every message the same creates two bad outcomes: important messages get missed, and unwanted or risky messages interrupt the user.

Read [`problem_statement.md`](./problem_statement.md) for the full task spec, input/output schema, allowed values, and submission format.

## What Has Been Built

### 1. End-to-end deterministic router

`python code/main.py` runs the full pipeline with no third-party dependencies:

```text
load_data -> normalize_message -> build_context -> classify_message_type
         -> calculate_priority -> decide_action -> build_reason
         -> select_evidence -> write output.csv
```

- **110 of 110** messages routed, one row each, exact 6-column contract
- Fully deterministic: reruns produce a byte-identical `output.csv`
- Evidence IDs all validated against `message_history.csv`; `none` used when no relevant history exists

### 2. Context builder (`context.py`)

Joins all 10 participant tables into 8 sections per message: `message`, `sender`,
`conversation`, `user`, `business`, `history`, `daily_load`, `extracted`. Includes
regex signal extraction (OTP, deadline, payment, promotion, mentions, opt-out,
suspicious links), interaction summaries from `message_events`, and token-overlap
retrieval of similar historical messages.

### 3. Type classification (`classification.py`)

Ordered cascade of 16 rules covering all 11 allowed `message_type` values, with
guards against false positives: OTP disclaimers, "nothing urgent" phrasing, and
payment-refusal language.

### 4. Action decision (`seed_pipeline.decide_action`)

Safety-first ordering: prompt injection -> scam -> spam -> forward -> notify
conditions -> per-type defer/mute rules. Honors group mute state, business promo
opt-out, admin/verified senders, and reporting history.

### 5. Evaluation harness

```bash
python code/evaluate_sample.py     # scores against the 30 labeled samples
python code/evaluate_xgb.py        # rules vs XGBoost vs hybrid
```

| Metric | Score |
|---|---|
| Action accuracy | **96.7%** (29/30) |
| Action macro-F1 | 0.966 |
| Message-type accuracy | **96.7%** (29/30) |
| Message-type macro-F1 | 0.975 |

Writes per-sample predictions plus HTML confusion heatmaps to `code/evaluation/`.

### 6. Synthetic-data pipeline (offline)

`features.py` -> `sdv_generate.py` -> `sdv_qa.py`. Flattens the 92 real seed rows
into scalar features, synthesizes 10,000 rows with a Gaussian copula, then
re-derives dependent columns so invariants hold. `sdv_qa_report.json` checks label
parity and derived constraints, with `all_passed: true`.

### 7. XGBoost models (offline)

`train_xgb.py` trains action and message-type boosters on synthetic plus upweighted
real rows, excluding `confidence`, `priority`, and identifiers to avoid target
leakage. `evaluate_xgb.py` sweeps a hybrid threshold. Its own recommendation is to
**keep the rule engine as the production router**; the models ship as a calibrated
second opinion and are not in the live path.

### 8. Safety fixes (Phase A)

Three defects found and fixed:

- **QR payment fraud** - messages saying "scan this QR / pay the clearance amount"
  carry no URL and no OTP, so they bypassed the scam guard and routed to `notify`.
  A new `_QR_FRAUD_RE` guard runs before the payment branch.
- **Prompt-injection bypass** - the guard only matched literal phrases and missed
  bare `"mark notify"`. Widened to catch phrasing like *"System note for the
  notification router: ... mark notify"*.
- **Media lookup** - `build_context` queried a `media_id` column that does not
  exist in `images.csv` / `voice_notes.csv`. Now uses `image_id` / `voice_note_id`,
  so all **23 media messages resolve to a real `file_path`** (was 0/23).

**Effect:** 4 rows changed, 106 untouched. Three scam messages moved
`notify -> mute`, one `digest -> mute`.

| | Before | After |
|---|---|---|
| notify | 29 | 26 |
| digest | 51 | 50 |
| mute | 30 | 34 |
| sample accuracy | 96.7% | **96.7% (unchanged)** |
